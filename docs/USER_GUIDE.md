# دليل مستخدم عَوْن

- **الإصدار المشروح:** `v0.1.0-dev` — النواة المحلية
- **نظام التشغيل المستهدف حاليًا:** Windows
- **عنوان لوحة التحكم:** `http://127.0.0.1:3000/`

هذا الدليل يشرح تشغيل عَوْن محليًا، وإجراء التهيئة الأولى، وإنشاء المحادثات وإرسال الطلبات، ثم إيقاف التطبيق ومعالجة المشكلات الشائعة.

> **حالة النسخة الحالية:** عَوْن ما زال في مرحلة التطوير. تحفظ الواجهة المستخدم ومساحة العمل والمحادثات والتشغيلات والخطط والموافقات واستدعاءات الأدوات والمهام وأوامر الإلغاء في PostgreSQL. يستطيع المنسق إنتاج إجابة أو خطة أو طلب توضيح، وينفذ حاليًا أداتين داخليتين بعد موافقة مطابقة: إنشاء مهمة، وإنشاء ملف داخل جذر مساحة عمل آمن. يمكن إلغاء العمل المنتظر أو الجاري مع عرض صادق لما توقف وما تعذر تأكيده. لا توجد أدوات خارجية مفعلة بعد.

## 1. مكونات التطبيق

يتطلب الاستخدام المحلي تشغيل أربعة مكونات:

| المكوّن | وظيفته | حالته أثناء الاستخدام |
|---|---|---|
| PostgreSQL | حفظ بيانات المستخدم والمحادثات والتشغيلات | يعمل كخدمة Windows في الخلفية |
| خدمة عَوْن الخلفية | معالجة طلبات الواجهة والوصول الآمن إلى البيانات | نافذة PowerShell على المنفذ `8000` |
| عامل عَوْن | تنفيذ الأدوات المدرجة واستعادة العمل بعد الانقطاع | نافذة PowerShell مستقلة بلا منفذ ويب |
| لوحة التحكم | الواجهة العربية التي تستخدمها في المتصفح | نافذة PowerShell على المنفذ `3000` |

PostgreSQL ليس لوحة تحكم ولا يُفتح في المتصفح؛ لوحة التحكم هي تطبيق الويب الموجود على المنفذ `3000`.

## 2. التشغيل اليومي السريع

### الخطوة 1 — التأكد من PostgreSQL

افتح PowerShell ونفّذ:

```powershell
Get-Service -Name "postgresql*"
```

يجب أن تكون قيمة `Status` هي `Running`. إذا كانت الخدمة متوقفة، افتح PowerShell بصفة مسؤول ثم نفّذ:

```powershell
Get-Service -Name "postgresql*" | Start-Service
```

### الخطوة 2 — تشغيل خدمة عَوْن الخلفية

في نافذة PowerShell الأولى:

```powershell
Set-Location "E:\OpenAI_Codex\Awn"
.\.venv\Scripts\python.exe -m uvicorn apps.api.main:app --host 127.0.0.1 --port 8000
```

اترك النافذة مفتوحة. ظهور السطر التالي يعني أن الخدمة تعمل:

```text
Uvicorn running on http://127.0.0.1:8000
```

يمكنك التحقق منها بفتح:

- `http://127.0.0.1:8000/ready` — يجب أن يعرض حالة `ready` وقاعدة `postgresql`.
- `http://127.0.0.1:8000/docs` — توثيق API التقني، وليس لوحة المستخدم.

### الخطوة 3 — تشغيل عامل عَوْن

افتح نافذة PowerShell ثانية ونفّذ:

```powershell
Set-Location "E:\OpenAI_Codex\Awn"
.\.venv\Scripts\python.exe -m apps.worker.main
```

اترك النافذة مفتوحة. يتابع العامل طابور PostgreSQL، ويستعيد أي حجز انتهت مهلته بعد توقف سابق. قد تنفذ API دورة فورية بأفضل جهد بعد الموافقة، لكن العامل المستقل هو ضمان الاستعادة ولا ينبغي إيقافه أثناء الاستخدام.

### الخطوة 4 — تشغيل لوحة التحكم

افتح نافذة PowerShell ثالثة ونفّذ:

```powershell
Set-Location "E:\OpenAI_Codex\Awn\apps\web"
npm run dev
```

اترك هذه النافذة مفتوحة أيضًا. ظهور `Ready` وعنوان المنفذ `3000` يعني أن الواجهة تعمل.

### الخطوة 5 — فتح التطبيق

افتح العنوان الكامل التالي في المتصفح:

`http://127.0.0.1:3000/`

لا تستخدم `127.0.0.1` وحده؛ فهذا يحاول الاتصال بالمنفذ `80` بدل منفذ لوحة عَوْن.

قد يستغرق الفتح الأول عدة ثوانٍ بينما تجهز Next.js ملفات التطوير.

## 3. التهيئة الأولى

تظهر شاشة **لنُنشئ مساحتك الخاصة** عند أول تشغيل فقط.

1. في حقل **الاسم المعروض** اكتب الاسم الذي تريد أن يستخدمه عَوْن في الواجهة.
2. في حقل **اسم مساحة العمل الأولى** اكتب اسمًا يصف نطاق أعمالك، أو اترك القيمة الافتراضية `مساحة عَوْن`.
3. اضغط **إنشاء مساحتي**.
4. انتظر انتقالك إلى لوحة التحكم.

تُحفظ هذه البيانات في PostgreSQL على الجهاز. لا توجد حاليًا شاشة لتعديل ملف المستخدم أو إعادة ضبطه؛ ستضاف لاحقًا.

## 4. التعرف إلى لوحة التحكم

بعد التهيئة ستظهر العناصر التالية:

| العنصر | الاستخدام |
|---|---|
| مساحة العمل | تعرض المساحة الحالية وتسمح بالتبديل عندما توجد عدة مساحات |
| مساحات العمل | عدد المساحات المرتبطة بالمستخدم المحلي |
| المحادثات | عدد المحادثات في المساحة الحالية |
| المهام | عدد المهام في المساحة الحالية وقائمة العمل المحفوظة |
| التشغيلات النشطة | كل الطلبات التي لم تصل إلى حالة نهائية؛ يمكن اختيار كل تشغيل بمعرفه المختصر وطلب إلغائه منفردًا |
| جلسات العمل | إنشاء محادثة واختيار محادثة سابقة |
| المحادثة الحالية | عرض الرسائل وحالة آخر تشغيل وإرسال طلب جديد |
| متصل | يعني أن لوحة التحكم استطاعت الوصول إلى خدمة عَوْن الخلفية |

ينقلك عنصر **المهام** في القائمة الجانبية إلى قائمة العمل. تعرض المحادثة الحالية قائمة تشغيلاتها النشطة، ويؤدي اختيار تشغيل إلى عرض خطته وموافقته وسجل أداته وحالة إلغائه من دون الخلط بين تشغيلين متزامنين. أما شاشة التشغيلات المستقلة في القائمة الجانبية فما زالت تحمل علامة `قريبًا`.

## 5. إنشاء محادثة

1. انتقل إلى قسم **جلسات العمل**.
2. اكتب عنوانًا واضحًا في حقل **عنوان محادثة جديدة**، مثل `تطوير موقع الشركة`.
3. اضغط زر `＋`.
4. ستصبح المحادثة الجديدة هي المحادثة الحالية تلقائيًا.

استخدم محادثة مستقلة لكل مشروع أو موضوع حتى يبقى السياق منظمًا.

## 6. إرسال طلب إلى عَوْن

1. اختر المحادثة المطلوبة من قائمة **جلسات العمل**.
2. اختر **مستوى التفويض** قبل الإرسال:
   - **استشاري — خطة فقط:** لا يسمح بأي أثر دائم.
   - **منفّذ بإذن — موافقة قبل الأثر:** يسمح بإعداد إجراء ثم ينتظر موافقة صريحة قبل تنفيذه.
3. اكتب طلبك في الحقل السفلي **اكتب ما تريد من عَوْن إنجازه**.
4. اضغط **إرسال إلى عَوْن**.
5. تحفظ الرسالة ويُنشأ لها تشغيل بدرجة مخاطر أولية منخفضة ومستوى التفويض المختار.
6. تظهر حالة التشغيل بجانب عنوان المحادثة، ثم تتحدث الرسائل والخطة تلقائيًا.

مثال لطلب واضح:

```text
حلل متطلبات صفحة تسجيل الدخول، واقترح خطة تنفيذ مرتبة مع معايير قبول.
```

يحلل المنسق الطلب بعد حفظه، ثم يعرض أحد المسارات التالية:

- **إجابة:** تظهر رسالة عَوْن وتصبح حالة التشغيل **مكتمل**.
- **خطة بلا أثر حساس:** تظهر رسالة عَوْن وبطاقة **الخطة المقترحة** وخطواتها، وتصبح الحالة **جاهز**.
- **خطة تحتاج موافقة:** تظهر الخطة وبطاقة **طلب موافقة**، وتصبح الحالة **بانتظار الموافقة**.
- **طلب توضيح:** يسأل عَوْن عن المعلومة الناقصة وتصبح الحالة **يحتاج توضيحًا**.

قد تظهر حالتا **مستلم** و**يخطط** لفترة قصيرة. ظهور الخطة أو حالة **جاهز** لا يعني أن الطلب نُفذ. يبدأ الأثر فقط بعد موافقة صالحة على خطوة تحمل معرف أداة مسجلة؛ وتظهر نتيجة التنفيذ في بطاقة **سجل الأداة**.

مزود النموذج الوهمي هو الافتراضي، ويعطي نتائج حتمية للتجربة دون مفتاح API. للحصول على تخطيط وإجابات من OpenAI، اضبط `AWN_MODEL_PROVIDER=openai` و`AWN_OPENAI_MODEL` و`AWN_OPENAI_API_KEY` في ملف `.env` المحلي ثم أعد تشغيل خدمة API. لا تشارك هذا الملف أو تضفه إلى Git.

## 7. مراجعة طلب الموافقة

عندما تتضمن الخطة خطوة ذات أثر أو حساسية، تظهر بطاقة **طلب موافقة** أسفل الخطة:

1. راجع جميع خطوات الخطة، وخصوصًا الخطوات التي تحمل عبارة **يحتاج موافقة** ودرجة المخاطر.
2. راجع ملخص الإجراء وبصمته ذات 64 خانة سداسية. البصمة تربط القرار بالخطة المعروضة نفسها.
3. اضغط **مراجعة واعتماد الخطة** إذا كانت مطابقة لطلبك. إذا احتوت الخطة أداة مسجلة، تُستهلك الموافقة مرة واحدة وينفذ عَوْن الإجراء ثم يعرض سجل الأداة والنتيجة.
4. اضغط **رفض وإلغاء التشغيل** إذا لم توافق؛ تتحول الحالة إلى **ملغي** ولن يستخدم عَوْن هذا الطلب.

تنتهي صلاحية الطلب بعد 30 دقيقة. إذا تغيرت الخطة بعد عرض الطلب، يبطل عَوْن الموافقة القديمة ويطلب مراجعة جديدة. لا تحاول نسخ بصمة من طلب آخر؛ يرفض الخادم أي بصمة غير مطابقة.

### إنشاء مهمة بواسطة عَوْن

1. اختر **منفّذ بإذن — موافقة قبل الأثر**.
2. ابدأ الطلب بعبارة واضحة، مثل: `أنشئ مهمة لمراجعة التقرير الأسبوعي`.
3. راجع خطوة `tasks.create` ومدخلها الظاهر في بطاقة الخطة.
4. اعتمد الخطة إذا كان عنوان المهمة صحيحًا.
5. يجب أن تصبح حالة التشغيل **مكتمل**، وحالة سجل الأداة `succeeded`، وأن تظهر المهمة في **قائمة العمل الحالية**.

تكرار زر الموافقة أو إعادة الطلب التقني للموافقة نفسها لا ينشئ مهمة ثانية؛ يرتبط الأثر باستدعاء أداة ذي مفتاح منع تكرار. في المزود المحلي الحتمي، يجب أن تبدأ صيغة إنشاء المهمة بإحدى عبارات «أنشئ مهمة» أو «أضف مهمة» أو المقابل الإنجليزي حتى تُقترح الأداة. الطلبات الأخرى تبقى إجابات أو خططًا بلا تنفيذ.

### إنشاء ملف آمن بواسطة عَوْن

1. اختر **منفّذ بإذن — موافقة قبل الأثر**.
2. استخدم الصيغة الواضحة التالية مع مسار نسبي ومحتوى:

   ```text
   أنشئ ملف تقارير/ملخص.txt بالمحتوى: هذا ملخص العمل اليومي.
   ```

3. راجع خطوة `files.create` والمسار والمحتوى في الخطة، ثم اعتمدها.
4. تعرض بطاقة سجل الأداة المسار النسبي عند النجاح. يوجد الملف محليًا تحت:

   ```text
   E:\OpenAI_Codex\Awn\data\workspaces\<معرف-مساحة-العمل>\تقارير\ملخص.txt
   ```

لا تقبل الأداة مسارًا مطلقًا أو `..` أو شرطة Windows العكسية `\`. ولا تستبدل ملفًا موجودًا مختلف المحتوى؛ إذا أعيد الاستدعاء نفسه بعد انقطاع ووجد المحتوى مطابقًا، تعده استعادة آمنة ولا تنشئ نسخة ثانية.

## 8. التنقل بين المحادثات

- اضغط اسم أي محادثة في قائمة **جلسات العمل** لعرض رسائلها وتشغيلاتها.
- تعرض القائمة وقت آخر تحديث للمحادثة.
- تُستعاد البيانات من PostgreSQL بعد إيقاف التطبيق وتشغيله مجددًا.
- لا تتوفر حاليًا أزرار حذف المحادثة أو أرشفتها أو إعادة تسميتها.

## 9. حالات التشغيل

تعرض لوحة التحكم الحالات التالية:

| الحالة | معناها |
|---|---|
| مستلم | حُفظ الطلب ولم يبدأ التخطيط بعد |
| يخطط | يجري إعداد خطة العمل |
| يحتاج توضيحًا | يلزم جواب من المستخدم قبل المتابعة |
| جاهز | الخطة جاهزة للمرحلة التالية |
| بانتظار الموافقة | يوجد إجراء يحتاج موافقة صريحة |
| قيد التنفيذ | يجري تنفيذ الخطوات المصرح بها |
| طُلب إلغاؤه | ثُبّت أمر الإلغاء، لكن توقف الأثر الجاري لم يُؤكد بعد |
| توقفه غير مؤكد | لا يوجد دليل حاسم على وقوع الأثر أو توقفه؛ لا تعد التنفيذ |
| يتحقق | يجري التحقق من النتيجة |
| مكتمل | اكتملت العملية بنجاح |
| مكتمل جزئيًا | نجحت بعض الخطوات وتعذر بعضها |
| فشل، مرفوض، ملغي | انتهى التشغيل دون إكمال النتيجة |

تعمل حالات الدورة كاملة للأداتين الداخليتين، من التخطيط وانتظار الموافقة إلى الإدراج في الطابور والتنفيذ والنجاح أو الفشل أو الإلغاء. تعرض بطاقة سجل الأداة **في طابور التنفيذ** عند انتظار العامل أو موعد إعادة محاولة، و**قيد التنفيذ** أثناء الحجز، و**النتيجة غير مؤكدة** إذا انتهت مهلة العامل بعد عبور حد الأثر بلا دليل نهائي. يستعيد عامل جديد الحجز المنتهي من دون احتساب الانقطاع محاولة إضافية، لكنه لا يطالب بعمل يحمل أمر إلغاء ولا يعيد محاولته.

## 10. إلغاء تنفيذ جارٍ

الفكرة الحاكمة هي: **الإلغاء فرامل، وليس ممحاة**. يمنع عَوْن ما لم يبدأ بعد، لكنه لا يدعي محو أثر وقع فعلًا.

1. افتح المحادثة التي تضم التشغيل.
2. في **التشغيلات النشطة**، تحقق من الوقت والمعرف المختصر حتى تختار التشغيل المقصود.
3. اضغط **إلغاء التنفيذ** في صف التشغيل. لا يحتاج الإلغاء إلى تأكيد ثانٍ لأنه فرامل عاجلة ولا ينشئ أثرًا جديدًا.
4. تظهر أولًا عبارة **جارٍ إرسال طلب الإلغاء**؛ وهي لا تعني أن الخادم استلمه.
5. بعد تثبيت الأمر تظهر بطاقة مستقلة. تابعها حتى تعرض الحقيقة النهائية أو حالة عدم اليقين.

قد تعرض البطاقة إحدى النتائج التالية:

| النتيجة | معناها | ما ينبغي فعله |
|---|---|---|
| قُبل الطلب؛ يجري التحقق | الأمر محفوظ ويمنع أثرًا جديدًا، لكن الجاري لم يُحسم | لا تبدأ تشغيلًا بديلًا |
| أُلغي قبل الأثر | ثبت أن الأثر لم يبدأ | لا إجراء لازم |
| وقع أثر جزئي وتوقف الباقي | بعض الأثر وقع، ومنع عَوْن المتبقي | راجع الأثر؛ لا يوجد تعويض تلقائي |
| اكتمل الأثر وكان الإلغاء متأخرًا | عبر التنفيذ نقطة التحكم وأثبتت النتيجة اكتماله | راجع النتيجة؛ لا تفترض التراجع |
| تعذر تأكيد التوقف | الدليل لا يكفي للجزم | لا تعاود التنفيذ؛ راجع آخر دليل أو المورد |
| تعارض دليل النتيجة | وصل دليلان صحيحان متنافيان | لا تعاود التنفيذ؛ راجع الدليلين وتوقيتهما |
| توقف التنفيذ بسبب فشل | لا أثر ناجح مثبت، والفشل ليس إلغاءً مؤكداً | راجع رمز الخطأ قبل عمل جديد |

تظهر البطاقة وقت **استلام عَوْن للطلب** ووقت **تثبيت أمر الإلغاء** وآخر دليل تقني منقح. أحداث الدليل مرتبة ترتيبًا دائمًا، وأكوادها من قائمة داخلية مغلقة. وإذا تعارض دليلان، تعرض البطاقة الحالة السابقة وبصمتي الدليل ووقت كل منهما بدل إخفاء التعارض. الطلب المتكرر آمن ويعيد الأمر نفسه. إذا فقدت الواجهة استجابة الطلب، تتحقق منه تلقائيًا، وتنتقل إلى التشغيل الصحيح وتركز بطاقة الإلغاء عند العثور عليه؛ وإن لم تستطع التأكد تعرض رسالة المحاولة من جديد ولا تدعي القبول.

الأداتان الحاليتان عمليتان ذريتان قصيرتان: يستطيع عَوْن منعهما قبل حد الأثر، لكنه لا يعد بإيقافهما بعد عبوره. إذا انتهت مهلة العامل بعد الحد، تفحص المصالحة الدليل من دون إعادة الأداة؛ فتحسم الأثر المثبت، لكنها تبقي الحالة غير مؤكدة إذا لم تر المورد، لأن الغياب اللحظي لا يثبت أن الأثر لن يقع لاحقًا. تحتفظ أداة الملفات بإيصال أثر داخلي يبقى دليلاً حتى لو حُذف الملف الهدف لاحقًا. لا يوجد قتل قسري للعامل ولا تعويض تلقائي عن أثر مكتمل.

## 11. إيقاف التطبيق

1. انتقل إلى نافذة لوحة التحكم واضغط `Ctrl+C`.
2. انتقل إلى نافذة عامل عَوْن واضغط `Ctrl+C`.
3. انتقل إلى نافذة خدمة عَوْن الخلفية واضغط `Ctrl+C`.
4. يمكن ترك PostgreSQL يعمل كخدمة Windows تلقائية.

إغلاق نافذتي PowerShell يوقف الواجهة والخدمة الخلفية، لكنه لا يحذف البيانات المحفوظة.

## 12. معالجة المشكلات الشائعة

### تظهر `ERR_CONNECTION_REFUSED`

السبب: لوحة التحكم غير مشغلة، أو فُتح عنوان بلا المنفذ الصحيح.

الحل:

1. شغّل `npm run dev` من `E:\OpenAI_Codex\Awn\apps\web`.
2. افتح `http://127.0.0.1:3000/` كاملًا.
3. اترك نافذة PowerShell مفتوحة.

### تظهر «تعذر الوصول إلى نواة عَوْن»

السبب: الواجهة تعمل، لكن خدمة API على المنفذ `8000` متوقفة أو غير جاهزة.

الحل:

1. شغّل أمر Uvicorn الموضح في قسم التشغيل اليومي.
2. افتح `http://127.0.0.1:8000/ready` وتأكد من ظهور `ready`.
3. ارجع إلى لوحة التحكم واضغط **إعادة الاتصال**.

### يبقى سجل الأداة «في طابور التنفيذ»

السبب المعتاد: عامل عَوْن غير مشغل، أو أن الاستدعاء ينتظر موعد إعادة محاولة بعد خطأ مؤقت.

1. شغّل `python -m apps.worker.main` بالأمر الكامل في قسم التشغيل اليومي.
2. اترك النافذة مفتوحة وانتظر التحديث التلقائي للوحة خلال ثوانٍ.
3. إذا استمر الانتظار، راجع نافذة العامل ورمز الخطأ الظاهر في سجل الأداة، من دون مشاركة ملف `.env`.

### تبقى حالة «توقفه غير مؤكد»

تعني هذه الحالة أن العامل عبر حد الالتزام بالأثر ثم انتهت مهلته أو وصل دليل متعارض. ليست خطأ عرض، ولا تعني أن التنفيذ توقف.

1. لا ترسل الطلب نفسه من جديد، حتى لا تنشئ أثرًا إضافيًا.
2. افتح تفاصيل دليل الإلغاء وراجع آخر رمز ووقته.
3. تحقق من المورد نفسه، مثل قائمة المهام أو الملف المستهدف.
4. اترك العامل يعمل كي يفحص دليل المصالحة المتاح من دون إعادة تنفيذ الأداة. إذا كان الدليل مجرد غياب مورد فستبقى الحالة غير مؤكدة؛ وإذا بقي التعارض، يلزم تدخل يدوي ولا يحسمه عَوْن تلقائيًا في هذه النسخة.

### PostgreSQL غير جاهز

تحقق من الخدمة:

```powershell
Get-Service -Name "postgresql*"
```

إذا لم تكن البيئة قد أُعدت من قبل، نفّذ من مجلد المشروع:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\configure_postgres.ps1
.\.venv\Scripts\python.exe -m alembic upgrade head
```

أداة الإعداد تطلب كلمة مرور حساب `postgres` محليًا ولا تعرضها في السجل.

### الأمر `npm` غير معروف

ثبّت Node.js إصدار `20.9` أو أحدث، ثم أغلق PowerShell وافتحه مجددًا. للتحقق:

```powershell
node --version
npm --version
```

### حزم الواجهة غير مثبتة

نفّذ مرة واحدة:

```powershell
Set-Location "E:\OpenAI_Codex\Awn\apps\web"
npm ci
```

### بيئة Python غير موجودة

نفّذ مرة واحدة من مجلد المشروع:

```powershell
Set-Location "E:\OpenAI_Codex\Awn"
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m alembic upgrade head
```

### المنفذ مستخدم من برنامج آخر

اعرض البرنامج الذي يستمع على المنفذين:

```powershell
Get-NetTCPConnection -State Listen |
    Where-Object { $_.LocalPort -in 3000, 8000 } |
    Select-Object LocalAddress, LocalPort, OwningProcess
```

إذا كان عَوْن يعمل أصلًا في نافذة أخرى، استخدم تلك النسخة أو أغلقها بطريقة طبيعية باستخدام `Ctrl+C` قبل بدء نسخة جديدة.

## 13. الخصوصية وحدود الاستخدام الحالي

- تعمل الخدمات على `127.0.0.1`، لذلك لا تكون متاحة مباشرة للأجهزة الأخرى على الشبكة.
- لا تتصل لوحة التحكم بـPostgreSQL مباشرة؛ تمر الطلبات عبر خدمة عَوْن الخلفية.
- لا تضف ملف `.env` أو كلمات المرور أو مفاتيح API إلى Git.
- لا تستخدم هذه النسخة للنشر العام أو لحفظ بيانات شديدة الحساسية؛ أدوات التصدير والحذف والنسخ الاحتياطي لم تكتمل بعد.
- مزود النموذج الوهمي هو الافتراضي ولا يرسل محتوى المحادثة إلى خدمة خارجية. عند تفعيل OpenAI تُرسل حزمة السياق القريب اللازمة إلى Responses API مع `store=false`.
- المنسق لا ينفذ مخرجات النموذج مباشرة. الأداتان الداخليتان حاليًا هما إنشاء مهمة وإنشاء ملف آمن، وتمر كلتاهما عبر سجل الأدوات والسياسة والموافقة والطابور والتحقق. لا توجد آثار خارجية مفعلة.
- الموافقة محددة بالخطة والبصمة ومدة الصلاحية؛ تغيير الخطة يبطل الطلب بدل توسيع الإذن ضمنيًا.
- لا يقبل مسار الإلغاء سببًا حرًا أو تعليمات في جسم الطلب، ولا تعرض الواجهة رمز بوابة الأثر أو هوية العامل الداخلية. تحفظ أحداث الإلغاء أكوادًا تقنية منقحة من قائمة مغلقة فقط وتحذف مع التشغيل. لا يعتمد إثبات «عدم وقوع الأثر» على نص يرسله مستدعٍ ولا على غياب المورد اللحظي؛ يستخدم عامل المصالحة فاحصًا داخليًا ودليلًا دائمًا خاصًا بالأداة من دون إعادة تشغيلها.
