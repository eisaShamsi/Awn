# ADR-008: الموافقة المرتبطة ببصمة الإجراء

- **الحالة:** مقبول
- **التاريخ:** 2026-08-23

## السياق

الموافقة العامة أو الموافقة على وصف قابل للتغيير قد تسمح بتنفيذ خطة تختلف عما راجعه المستخدم. يجب أن تكون الموافقة محددة، قصيرة العمر، وقابلة للتحقق آليًا قبل أي أثر.

## القرار

- يحمل كل طلب موافقة بصمة SHA-256 لترميز JSON حتمي بالإصدار `awn.approval.v1`.
- تشمل البصمة العملية، ومعرفات التشغيل ومساحة العمل والمحادثة، ومستوى التفويض والمخاطر، ومعرف كل خطوة وترتيبها وعنوانها ومخاطرها ومتطلب الموافقة.
- يعرض التطبيق البصمة للمستخدم، ويرسل العميل البصمة نفسها مع قرار القبول أو الرفض.
- يعيد الخادم حساب البصمة من الخطة المحفوظة داخل معاملة مقفلة قبل تسجيل القرار؛ ويُبطل الطلب إذا تغيرت الخطة.
- تنتهي الموافقة بعد 30 دقيقة افتراضيًا، ويُلغي الرفض أو الانتهاء التشغيل الحالي.
- القرار المتكرر المطابق قابل للإعادة دون أثر جديد، أما القرار المتعارض فيُرفض.
- يعيد قرار القبول التشغيل إلى `ready`، ثم يستهلك منفذ الأدوات الموافقة ذريًا مع إنشاء استدعاء الأداة الدائم ونقل التشغيل إلى `executing`.
- إذا كانت الخطة لا تحتوي إجراء أداة مسجلًا، تبقى الموافقة مراجعة للخطة ولا ينشأ أثر.

## النتائج

- لا يمكن تبديل الإجراء بعد عرضه مع إعادة استخدام الموافقة القديمة.
- البصمة دليل مطابقة وليست سرًا أو توقيعًا؛ حماية قاعدة البيانات وحدود الهوية تبقى ضرورية.
- أي تعديل مقصود على الخطة يتطلب طلب موافقة جديدًا.
- يستهلك منفذ الأدوات الموافقة داخل معاملة مقفلة تمنع الاستخدام المتزامن، ويرتبط الأثر بمفتاح منع تكرار مشتق من البصمة والخطوة.
