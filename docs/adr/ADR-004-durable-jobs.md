# ADR-004: الأعمال الخلفية الدائمة

- **الحالة:** مقبول
- **التاريخ:** 2026-08-23

## السياق

قد تنتظر عملية عَوْن موافقة المستخدم أو خدمة خارجية، ويجب ألا تضيع عند إعادة تشغيل الخادم أو تتكرر آثارها بسبب إعادة المحاولة.

## القرار

- حفظ `Run` وخطواته ومحاولاته في PostgreSQL.
- بدء `v0.1` بطابور أعمال مستند إلى PostgreSQL وعامل منفصل.
- استخدام قفل صفوف ومعاملة قصيرة لحجز العمل، مع مدة lease تسمح بالاستعادة بعد تعطل العامل.
- فرض مفتاح منع تكرار لكل خطوة ذات أثر خارجي.
- إضافة Redis أو وسيط رسائل مستقل فقط عند ظهور حاجة مقاسة لا يحققها PostgreSQL.

## النتائج

- يقل عدد مكونات التشغيل في البداية ويظل سجل الحالة في مصدر واحد.
- يجب إبقاء عمليات الحجز قصيرة وتجنب تشغيل الأداة داخل معاملة قاعدة مفتوحة.
- قد يلزم وسيط متخصص لاحقًا عند ارتفاع الحمل أو الحاجة إلى توزيع واسع.
