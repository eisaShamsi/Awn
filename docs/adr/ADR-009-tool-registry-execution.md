# ADR-009: سجل الأدوات والتنفيذ المصرح القابل للإعادة

- **الحالة:** مقبول
- **التاريخ:** 2026-08-23

## السياق

لا يجوز للنموذج استدعاء شيفرة تطبيقية أو إحداث أثر دائم مباشرة. كما أن إعادة طلب HTTP أو تعطل العامل بعد بدء التنفيذ قد يكرر الأثر إن لم تكن نية الأداة، والموافقة، والاستدعاء، والنتيجة محفوظة ومترابطة.

## القرار

- يسجل كل تعريف أداة اسمًا وعملية ومخططي إدخال وإخراج وتصنيف مخاطر ونوع أثر ونطاقات صلاحية ومهلة ودعم منع التكرار.
- لا يقبل المنسق إلا إجراء يطابق تعريفًا مسجلًا، ويتحقق من مدخلاته بواسطة Pydantic قبل حفظ الخطة.
- يصدر محرك السياسة قرارًا حتميًا مستقلًا عن النموذج: سماح، أو طلب موافقة، أو منع، أو طلب توضيح.
- عند القبول، يعاد فحص الأداة ومدخلاتها والسياسة والبصمة. ثم تُستهلك الموافقة ويُنشأ `tool_call` وتنتقل الخطوة والتشغيل إلى التنفيذ داخل معاملة واحدة مقفلة.
- يحمل الاستدعاء مفتاح SHA-256 فريدًا مشتقًا من بصمة الموافقة والخطوة والأداة. تربط أداة `tasks.create` المهمة بمعرف الاستدعاء الفريد، فتُرجع المهمة نفسها عند إعادة المحاولة بدل إنشاء نسخة أخرى.
- لا يسجل التشغيل نجاحًا إلا بعد أن تعيد الأداة ناتجًا مطابقًا للمخطط ويُحفظ الأثر والنتيجة. يسجل الفشل صراحة ويلغي الاستدعاءات المتبقية.
- أول أداة منفذة هي `tasks.create`: داخلية، منخفضة المخاطر، قابلة للتراجع، ومقيدة بمساحة العمل الحالية. لا يفتح هذا القرار أي صلاحية لأداة خارجية.

## النتائج

- يصبح المسار قابلًا للتتبع من رسالة المستخدم إلى الخطة والموافقة واستدعاء الأداة والمهمة الناتجة.
- تكرار قرار القبول أو استئناف الاستدعاء نفسه لا ينشئ مهمة مكررة.
- يطبّق العامل الدائم وسياسة إعادة المحاولة وفق [ADR-010](ADR-010-leased-worker-retries.md)، وتظل قواعد هذا القرار هي بوابة الأداة قبل إدراج العمل.
- يجب أن يضيف كل تعريف أداة جديد اختبارات سياسة ومخطط وعزل ومنع تكرار قبل تسجيله.
