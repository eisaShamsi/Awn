# ADR-002: واجهة الويب وبروتوكولات الاتصال

- **الحالة:** مقبول
- **التاريخ:** 2026-08-23

## السياق

تحتاج واجهة عَوْن إلى دعم ممتاز للعربية وRTL، وعرض المحادثة والخطط والموافقات وتقدم الأعمال الطويلة، مع قابلية التطوير إلى تطبيق أوسع لاحقًا.

## القرار

- استخدام Next.js مع TypeScript وApp Router لبناء واجهة الويب.
- جعل اتجاه الصفحة واللغة جزءًا من التخطيط الأساسي، لا معالجة لاحقة.
- اعتماد `Calibri` خطًا أساسيًا للواجهة في هذه المرحلة، مع `Segoe UI` و`Arial` وخط النظام العام بدائل عند عدم توفره.
- استخدام REST للقراءة والأوامر، وServer-Sent Events لبث حالة التشغيل من الخادم إلى الواجهة.
- عدم استخدام WebSocket في `v0.1` ما لم تظهر حاجة لاتصال ثنائي مستمر.
- إبقاء قرار الصلاحية في الخادم؛ الواجهة تعرض القرار ولا تصنعه.

## النتائج

- يمكن تقديم تجربة عربية سريعة مع فصل واضح عن API.
- تحصل الواجهة على هوية طباعية موحدة على Windows، مع تدرج احتياطي يحافظ على قابلية القراءة في البيئات الأخرى.
- SSE أبسط للمسار الحالي أحادي الاتجاه وقابل للاستبدال عند الحاجة.
- يتطلب المستودع مساري جودة منفصلين لـPython وTypeScript.
