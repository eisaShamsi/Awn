## نطاق التجربة

أُعدت محادثة اصطناعية معزولة وتشغيل بحالة «قيد التنفيذ» بلا خطة أو أداة أو أثر، حتى يبقى زر **إلغاء التنفيذ** ظاهرًا بما يكفي لتجربة المالك. لم يُستخدم السيناريو لإثبات حالات الأثر الجزئي أو المكتمل أو غير المؤكد؛ تغطي الاختبارات الآلية وتدقيق BUILD تلك الحالات.

## التسلسل والنتائج

1. اختبر المالك أولًا رفض طلب موافقة حقيقي، وظهرت البطاقة بحالة **مرفوض** من دون تنفيذ المهمة. أثبت ذلك مسار رفض الموافقة فقط، لا إلغاء تنفيذ جارٍ.
2. أُنشئ تشغيل الاختبار الآمن بمعرف مختصر `da1fcb59`، وتحقق API من بقائه في حالة `executing` ومن عدم وجود أي استدعاء أداة.
3. في المحاولة الأولى عرضت الواجهة: «لم يتأكد قبول الإلغاء. يمكنك إعادة المحاولة بأمان»، ولم تدّع قبولًا غير مثبت. كشف التشخيص أن المنفذ `8000` كان تشغله نسخة API قديمة بدأت في 23 أغسطس ولا يحتوي مخططها مسار الإلغاء، مع نسخة عامل قديمة مكررة.
4. أُوقفت عمليتا API والعامل القديمتان المحددتان فقط، وبقي العامل الحالي والواجهة. بعد إعادة تشغيل API الحالية، ظهر مسار `/cancellation` في OpenAPI وبقي التشغيل `executing`.
5. أعاد المالك الضغط على **إلغاء التنفيذ**. أصبحت حالة التشغيل `cancelled`، وظهرت بطاقة **أُلغي قبل الأثر** والخطوة الآمنة «لا يلزم إجراء آخر» وخط زمني لاستلام الطلب وتثبيت أمر الإلغاء.
6. تحقق API من سجل إلغاء نهائي `cancelled` وحدثي `request_accepted` و`cancelled_no_effect` بدليل `NO_EFFECT_VERIFIED`، ومن قائمة استدعاءات أدوات فارغة.

## تنظيف بيانات الاختبار

بعد التقاط النتيجة حُذفت محادثة الاختبار الاصطناعية وحدها حذفًا نهائيًا، ضمن نطاق تحقق قبل الحذف يساوي:

- محادثة واحدة.
- رسالة واحدة.
- تشغيل واحد.
- سجل إلغاء واحد وحدثان.
- صفر خطوات وموافقات واستدعاءات أدوات.

أعاد التحقق اللاحق صفرًا للمحادثة والرسالة والتشغيل والإلغاء والأحداث. لم تُحذف مهمة أو ملف أو بيانات مالك أخرى. لم تُنسخ صورة المالك إلى المستودع.

## الملاحظات المستفادة

- تعمل استعادة فقدان رد الإلغاء كما صُممت: لا تدعي الواجهة القبول عند تعذر العثور على سجل الأمر، وتسمح بإعادة المحاولة بأمان.
- إغلاق نافذة PowerShell لا يضمن دائمًا انتهاء العملية الابنة في بيئة Windows الحالية؛ يجب استخدام `Ctrl+C` ثم التحقق من المنافذ عند إعادة التشغيل.
- يجب أن تربط تعليمات تجربة المالك كل خطوة بموقع القسم واسم العنصر والنتيجة المتوقعة وفق `SO-008`.
- الأداتان الحاليتان قصيرتان جدًا، لذلك استُخدم تشغيل بلا أثر لإتاحة نافذة تفاعل موثوقة؛ لا يغير ذلك منطق الإلغاء المنتج ولا يضيف أداة اختبار إلى المنتج.

## الخلاصة

نجحت تجربة المالك المرئية لمسار **الإلغاء قبل الأثر**، بما يشمل السلوك الصادق عند فشل المحاولة الأولى ثم نجاح الإعادة على API الحالية. أصدر المالك بعد ذلك قبولًا نهائيًا صريحًا لـ`FC-002 v0.3`، ولذلك أُغلقت دورة المفهوم والتصميم والبناء والتسليم والتجربة بحالة `ACCEPTED`.
