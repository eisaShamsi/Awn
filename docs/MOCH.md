## قواعد الإدامة

1. تُضاف لكل جلسة مادة مستقلة تحمل معرفًا بصيغة `MOCH-YYYY-MM-DD-NNN` وتوقيت `Asia/Dubai`.

5. إذا صُححت معلومة أو تغير قرار، يُضاف التصحيح مع تاريخه ولا يُمحى التاريخ السابق.
6. تُحدّث خانة «آخر تحديث» بعد كل حوار أو عمل جوهري، وتُغلق الجلسة عند اكتمالها أو الانتقال إلى جلسة جديدة.

### القرارات المعتمدة في الجلسة

- الاسم الرسمي للمساعد هو **عَوْن (Awn)**.
- النواة الحالية تطبيق محلي لمستخدم واحد، مع PostgreSQL لحفظ البيانات وDocker لتشغيل الخدمات اللازمة.
- لوحة التحكم تطبيق ويب مستقل عن PostgreSQL.
- الخط المعتمد للواجهة في المرحلة الحالية هو `Calibri` مع خطوط احتياطية مناسبة.
- يُعتمد `MoCh` ذاكرة إدارية للمحادثات، ويُعتمد ملف الأوامر الثابتة مرجعًا للتوجيهات الدائمة.
- يُعتمد `AGENTS.md` في جذر المستودع نقطة الدخول الرئيسة لتطوير عَوْن باستخدام Codex.
- لا تنفذ المرحلة 1 أدوات أو آثارًا خارجية؛ تقتصر على الإجابة والاستيضاح والخطة المحفوظة، ويبدأ التنفيذ الفعلي بعد محرك السياسات والموافقة.
- أُغلقت المرحلتان 0 و1، وبدأت المرحلة 2 بأولوية الموافقة المرتبطة ببصمة الإجراء.
- الموافقة صالحة للخطة والبصمة المعروضتين فقط لمدة 30 دقيقة؛ وتُبطل عند تغير الخطة، وتُستهلك مرة واحدة عند تنفيذ إجراء أداة مسجل.
- أول أداة منفذة هي `tasks.create` الداخلية منخفضة المخاطر؛ ولا توجد أداة خارجية مفعلة.
- تُدرج الأدوات المصرح بها في طابور PostgreSQL دائم، ويحجزها عامل مستقل لمدة محدودة؛ إعادة المحاولة الافتراضية ثلاث مرات للأخطاء المؤقتة فقط.
- أداة `files.create` داخلية منخفضة المخاطر، وتكتب ملفًا جديدًا تحت جذر مساحة العمل الآمن بمسار نسبي فقط ومن دون استبدال ملف مختلف.
- لا يبدأ تصميم وظيفة جديدة أو توسع جوهري قبل اعتماد المالك الشخصي لمفهومها المرقم والمُصدر.
- يفحص مجلس التدقيق مراحل التطوير مقابل مفهوم الوظيفة، ولا تمر النتيجة للمالك بوصفها جاهزة للتجربة إلا بقرار `READY_FOR_OWNER_TRIAL`.

### أبرز المخرجات

- وثائق المنتج والبنية وخارطة الطريق وسجل القرارات المعمارية.
- نواة Python وPostgreSQL وترحيلات Alembic والاختبارات وGitHub Actions.
- نماذج المستخدم ومساحة العمل والمحادثات والتشغيلات وواجهات API الأساسية.
- لوحة تحكم عربية مبنية بـNext.js ودليل مستخدم عربي.
- معالجة محدودة لتحذير hydration الناتج عن إضافات المتصفح.
- منسق ذو عقد مخرجات منظم، مع بوابة OpenAI Responses API بخيار `store=false` ومزود محلي حتمي للاختبار.
- عرض الخطة المحفوظة والمخاطر ومتطلب الموافقة في لوحة التحكم مع تحديث تلقائي.
- [نموذج تهديد وسياسة بيانات](THREAT_MODEL.md) وقائمة GitHub Issues مرتبطة بالمراحل.
- نموذج وAPI وواجهة لطلب الموافقة والقبول والرفض وفق [ADR-008](adr/ADR-008-approval-fingerprint.md).
- سجل أدوات بعقود إدخال وإخراج ومخاطر، ومحرك سياسة مستقل، وتنفيذ ذري قابل للإعادة وفق [ADR-009](adr/ADR-009-tool-registry-execution.md).
- أداة داخلية لإنشاء المهام، وسجل دائم لاستدعاءات الأدوات، وقائمة مهام ظاهرة في لوحة التحكم.
- عامل مستقل قابل لاستعادة الحجوزات المنتهية وإعادة المحاولة المحدودة وفق [ADR-010](adr/ADR-010-leased-worker-retries.md).
- أداة `files.create` وحدود مسارات وعزل ملفات مساحة العمل وفق [ADR-011](adr/ADR-011-safe-workspace-files.md).
- [سجل مفاهيم الوظائف](FUNCTION_CONCEPTS.md)، و[ميثاق مجلس التدقيق](AUDIT_COUNCIL.md)، ومهارة المستودع `$awn-audit-council`، وقرار [ADR-012](adr/ADR-012-function-concept-audit-gate.md).

### الحالة عند آخر تحديث

- آخر فحوصات المشروع المحلية ناجحة: `45 passed` مع PostgreSQL و`1 skipped` لحماية المستخدم المحلي، وRuff، وlint، وفحص TypeScript، وبناء Next.js وتدقيق الحزم بلا ثغرات. نجحت ترقية PostgreSQL المحلية إلى `20260823_0005` وفحص عدم وجود فرق ترحيل، واختبار حجز واستعادة فعلي على PostgreSQL. تعمل API الجديدة على `127.0.0.1:8000` والعامل المستقل، وتعيد طبقة BFF حالة `ready` على لوحة `127.0.0.1:3000`.
- لا توجد مسألة فنية مفتوحة ناتجة عن تحذير hydration.
- المرحلة 2 قيد التنفيذ؛ اكتمل العامل القابل للاستئناف وإعادة المحاولة وأداتا المهمة والملف. أصبح `FC-002 v0.3` للإلغاء الآمن جاهزًا بتوصية المجلس `APPROVE_AS_WRITTEN`، وينتظر اعتماد المالك الشخصي قبل أي تصميم أو شيفرة.
- أُغلقت [Issue #4](https://github.com/eisaShamsi/Awn/issues/4) بعد استيفاء معاييرها، وتبقى [Issue #2](https://github.com/eisaShamsi/Awn/issues/2) مفتوحة للأدوات الداخلية المتبقية.
