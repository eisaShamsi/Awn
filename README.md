# عَوْن | Awn

> مساعد شخصي ذكي، عربيّ الهوية، يساند صاحبه في إدارة أعماله وبناء الحلول التقنية وإنجاز المهام بكفاءة وأمان.

**عَوْن** في العربية هو المساعدة والمعونة، ويُطلق كذلك على من يُستعان به ويُعتمد عليه في إنجاز أمر. يهدف المشروع إلى تحويل هذا المعنى إلى وكيل ذكي يفهم السياق، ويخطط، ويستخدم الأدوات، وينفّذ ضمن صلاحيات واضحة يحددها المستخدم.

> Awn is an Arabic-first personal AI agent for executive assistance, technical problem-solving, and safe, permission-aware execution.

## حالة المشروع

المشروع حاليًا في **مرحلة النواة المحلية (Local Core)**. لا يوجد إصدار جاهز للاستخدام اليومي بعد، لكن قاعدة البيانات وواجهات API الأساسية ولوحة التحكم العربية أصبحت قابلة للتشغيل والاختبار.

الهدف الأول هو بناء إصدار `v0.1` لمستخدم واحد يثبت دورة العمل الأساسية:

1. فهم طلب المستخدم وسياقه.
2. إعداد خطة قابلة للمراجعة.
3. طلب الموافقة عند الحاجة.
4. تنفيذ المهمة بالأدوات المصرح بها.
5. التحقق من النتيجة وتسجيل ما حدث.

## ما الذي سيقوم به عَوْن؟

- تنظيم المهام والمواعيد والمتابعات.
- إعداد الرسائل والتقارير والوثائق والملخصات.
- البحث وتحويل المعلومات إلى قرارات وخطوات عملية.
- تطوير حلول تقنية والعمل داخل المشروعات البرمجية.
- تذكّر التفضيلات والقرارات المهمة بصورة قابلة للمراجعة والحذف.
- تنفيذ الإجراءات الخارجية وفق مستويات تفويض وحدود واضحة.

## مبادئ التصميم

- **المستخدم صاحب القرار:** لا تُنفّذ الإجراءات الحساسة دون تفويض مناسب.
- **العربية أولًا:** تجربة عربية ممتازة مع دعم كامل للإنجليزية.
- **الخصوصية أصل في التصميم:** أقل قدر لازم من البيانات والصلاحيات.
- **قابلية التدقيق:** لكل إجراء سبب وخطة ونتيجة وسجل واضح.
- **الصدق بشأن القدرة:** لا يدّعي عَوْن تنفيذ ما لم ينفذه أو التحقق مما لم يتحقق منه.
- **التدرج في الاستقلالية:** تبدأ الصلاحيات محدودة وتتوسع بقرار المستخدم.
- **البساطة قبل التوزيع:** بنية موحّدة قابلة للتقسيم عندما تثبت الحاجة.

## مستويات التفويض

| المستوى | الدور | ما المسموح به |
|---|---|---|
| 0 — استشاري | يفكر ويقترح | لا ينفذ أي إجراء خارجي |
| 1 — مُعِدّ | يجهز ناتجًا للمراجعة | ينشئ مسودات وخططًا دون إرسال أو نشر |
| 2 — منفّذ بإذن | ينفذ بعد موافقة صريحة | يعرض الإجراء وأثره ثم ينتظر الموافقة |
| 3 — مفوّض | ينفذ ضمن سياسة مسبقة | يعمل تلقائيًا داخل نطاق وحدود قابلة للإلغاء |

لا يكفي مستوى التفويض وحده: الإجراءات عالية الخطورة تتطلب موافقة صريحة دائمًا.

## نطاق الإصدار الأول `v0.1`

- محادثة عربية وإنجليزية ذات جلسات محفوظة.
- ملف مستخدم وتفضيلات أساسية.
- مهام ومواعيد وملاحظات داخلية.

- سجل أدوات موحد مع أول تكامل عملي واحد على الأقل.
- موافقات قبل الإجراءات الخارجية أو الحساسة.
- سجل تدقيق ونتيجة موثقة لكل تنفيذ.
- بيئة تطوير محلية واختبارات للمسارات الحرجة.

خارج نطاق `v0.1`: تعدد المستخدمين، الاستقلالية المفتوحة، المعاملات المالية، تطبيقات الهاتف الأصلية، وتشغيل تعليمات مجهولة المصدر دون عزل.

## البنية في سطر واحد

واجهة مستخدم تتصل بخدمة تطبيق موحّدة تضم منسق الوكيل، ومحرك السياسات، وسجل الأدوات، والذاكرة، وطابور الأعمال، وسجل التدقيق؛ ويمكن فصل هذه الوحدات إلى خدمات مستقلة عند الحاجة.

## تشغيل النواة محليًا

تحتاج إلى Python `3.12+` وPostgreSQL. بوابة النماذج الوهمية هي الافتراضية، ولذلك لا يلزم مفتاح API لتشغيل الاختبارات أو تجربة API الحالية.

### PostgreSQL مثبت على Windows — المسار الموصى به حاليًا

```powershell
cd E:\OpenAI_Codex\Awn
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"

# عند عدم تثبيت PostgreSQL 18 بعد:
winget install --id PostgreSQL.PostgreSQL.18 --exact --interactive

# يفتح نافذة مسؤول ويطلب كلمة postgres محليًا دون عرضها.
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\configure_postgres.ps1

alembic upgrade head
pytest
uvicorn apps.api.main:app --reload
```

تنشئ أداة الإعداد قاعدة `awn` وحساب `awn_app` محدود الصلاحيات بكلمة عشوائية، وتقصر PostgreSQL على `localhost` مع `SCRAM-SHA-256`، ثم تكتب ملف `.env` محليًا بصلاحيات Windows مقيدة وتطبق الترحيلات. لا تضف ملف `.env` إلى Git.

### Docker — البديل عند الحاجة إلى بيئة حاويات

```powershell
docker compose up -d database
alembic upgrade head
```

يتطلب هذا البديل Docker Desktop وWSL 2 على Windows. تستخدم الاختبارات السريعة SQLite معزولة، بينما يشغّل CI واختبار التكامل المحلي قاعدة PostgreSQL حقيقية عند ضبط `AWN_TEST_POSTGRES_URL`.

بعد التشغيل:

- فحص الخدمة: `http://127.0.0.1:8000/health`
- فحص جاهزية قاعدة البيانات: `http://127.0.0.1:8000/ready`
- توثيق API التفاعلي: `http://127.0.0.1:8000/docs`

### تشغيل لوحة التحكم

تحتاج الواجهة إلى Node.js `20.9+` (ويُوصى بـNode.js 24). اترك API يعمل، ثم افتح نافذة PowerShell ثانية:

```powershell
cd E:\OpenAI_Codex\Awn\apps\web
npm ci
npm run dev
```

افتح `http://127.0.0.1:3000`. تتصل لوحة التحكم بالخادم عبر طبقة BFF محلية مقيّدة؛ لا تصل إلى PostgreSQL مباشرة ولا تُرسل عنوان API أو أسراره إلى المتصفح.

> **تنبيه أمني مؤقت (2026-08-23):** هذه الواجهة مخصصة للتطوير المحلي فقط. أعلن فريق Next.js [إصدارًا أمنيًا مجدولًا](https://nextjs.org/blog/upcoming-nextjs-security-release-august-2026) في 2026-08-26؛ يجب ترقية Next.js إلى الإصدار المصحح وإعادة فحوص الأمان والبناء قبل أي نشر شبكي أو إنتاجي.

### تهيئة النواة وتجربة المحادثة

بعد تشغيل API، استخدم صفحة `/docs` أو أرسل الطلبات التالية بالترتيب:

1. `POST /api/v1/setup` لإنشاء المستخدم المحلي ومساحة العمل الأولى بصورة قابلة للتكرار.
2. `POST /api/v1/workspaces/{workspace_id}/conversations` لإنشاء محادثة.
3. `POST /api/v1/workspaces/{workspace_id}/conversations/{conversation_id}/messages` لإضافة رسالة مستخدم منظمة.
4. `POST /api/v1/workspaces/{workspace_id}/conversations/{conversation_id}/runs` لإنشاء تشغيل مرتبط بالرسالة.
5. استخدم مسارات `GET` المقابلة لمتابعة المحادثات والرسائل وحالات التشغيل وخطواتها.
6. إذا احتوت الخطة أثرًا يستلزم موافقة، استخدم `GET .../runs/{run_id}/approvals` ثم `POST .../approvals/{approval_id}/decision` بالبصمة المعروضة والقرار `approve` أو `reject`.

جميع استعلامات المحادثات والتشغيلات والموافقات مقيدة بمستخدم عَوْن المحلي ومساحة العمل. لا تسمح API العامة بإنشاء رسالة بدور `assistant` أو تعيين درجة المخاطر أو تغيير حالة التشغيل مباشرة؛ ينشئ المنسق الداخلي إجابة أو خطة منظمة أو طلب توضيح ويحفظ النتيجة. ترتبط الموافقة ببصمة حتمية قصيرة العمر وتُبطل إذا تغيرت الخطة، لكنها لا تشغّل أداة أو أثرًا خارجيًا بعد.

لاستخدام OpenAI، انسخ `.env.example` إلى `.env`، واختر `AWN_MODEL_PROVIDER=openai` ثم عيّن `AWN_OPENAI_MODEL` و`AWN_OPENAI_API_KEY`. لا تضف ملف `.env` إلى Git.

## المساهمة

قبل بدء أي تغيير:

1. راجع [PRODUCT.md](PRODUCT.md) للتأكد من أن التغيير داخل النطاق.
2. وثّق أي قرار معماري مؤثر في سجل قرارات معماري عند بدء التنفيذ.
3. أضف اختبارًا ومعيار قبول لأي سلوك جديد.
4. لا تضف أداة خارجية دون تعريف صلاحياتها ومخاطرها وآلية إيقافها.

راجع [نموذج التهديد وسياسة البيانات](docs/THREAT_MODEL.md) قبل توسيع الصلاحيات أو إضافة تكامل خارجي.
