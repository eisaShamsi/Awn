# عَوْن | Awn

> مساعد شخصي ذكي، عربيّ الهوية، يساند صاحبه في إدارة أعماله وبناء الحلول التقنية وإنجاز المهام بكفاءة وأمان.

**عَوْن** في العربية هو المساعدة والمعونة، ويُطلق كذلك على من يُستعان به ويُعتمد عليه في إنجاز أمر. يهدف المشروع إلى تحويل هذا المعنى إلى وكيل ذكي يفهم السياق، ويخطط، ويستخدم الأدوات، وينفّذ ضمن صلاحيات واضحة يحددها المستخدم.

> Awn is an Arabic-first personal AI agent for executive assistance, technical problem-solving, and safe, permission-aware execution.

## حالة المشروع

المشروع حاليًا في **مرحلة التأسيس والتصميم (Foundation)**. لا يوجد إصدار جاهز للاستخدام بعد.

الهدف الأول هو بناء إصدار `v0.1` لمستخدم واحد يثبت دورة العمل الأساسية:

1. فهم طلب المستخدم وسياقه.
2. إعداد خطة قابلة للمراجعة.
3. طلب الموافقة عند الحاجة.
4. تنفيذ المهمة بالأدوات المصرح بها.
5. التحقق من النتيجة وتسجيل ما حدث.

## ما الذي سيقوم به عَوْن؟

- تنظيم المهام والمواعيد والمتابعات.
- إعداد الرسائل والتقارير والوثائق والملخصات.
- البحث وتحويل المعلومات إلى قرارات وخطوات عملية.
- تطوير حلول تقنية والعمل داخل المشروعات البرمجية.
- تذكّر التفضيلات والقرارات المهمة بصورة قابلة للمراجعة والحذف.
- تنفيذ الإجراءات الخارجية وفق مستويات تفويض وحدود واضحة.

## مبادئ التصميم

- **المستخدم صاحب القرار:** لا تُنفّذ الإجراءات الحساسة دون تفويض مناسب.
- **العربية أولًا:** تجربة عربية ممتازة مع دعم كامل للإنجليزية.
- **الخصوصية أصل في التصميم:** أقل قدر لازم من البيانات والصلاحيات.
- **قابلية التدقيق:** لكل إجراء سبب وخطة ونتيجة وسجل واضح.
- **الصدق بشأن القدرة:** لا يدّعي عَوْن تنفيذ ما لم ينفذه أو التحقق مما لم يتحقق منه.
- **التدرج في الاستقلالية:** تبدأ الصلاحيات محدودة وتتوسع بقرار المستخدم.
- **البساطة قبل التوزيع:** بنية موحّدة قابلة للتقسيم عندما تثبت الحاجة.

## مستويات التفويض

| المستوى | الدور | ما المسموح به |
|---|---|---|
| 0 — استشاري | يفكر ويقترح | لا ينفذ أي إجراء خارجي |
| 1 — مُعِدّ | يجهز ناتجًا للمراجعة | ينشئ مسودات وخططًا دون إرسال أو نشر |
| 2 — منفّذ بإذن | ينفذ بعد موافقة صريحة | يعرض الإجراء وأثره ثم ينتظر الموافقة |
| 3 — مفوّض | ينفذ ضمن سياسة مسبقة | يعمل تلقائيًا داخل نطاق وحدود قابلة للإلغاء |

لا يكفي مستوى التفويض وحده: الإجراءات عالية الخطورة تتطلب موافقة صريحة دائمًا.

## نطاق الإصدار الأول `v0.1`

- محادثة عربية وإنجليزية ذات جلسات محفوظة.
- ملف مستخدم وتفضيلات أساسية.
- مهام ومواعيد وملاحظات داخلية.
- ذاكرة مقترحة لا تُعتمد إلا بموافقة المستخدم.
- سجل أدوات موحد مع أول تكامل عملي واحد على الأقل.
- موافقات قبل الإجراءات الخارجية أو الحساسة.
- سجل تدقيق ونتيجة موثقة لكل تنفيذ.
- بيئة تطوير محلية واختبارات للمسارات الحرجة.

خارج نطاق `v0.1`: تعدد المستخدمين، الاستقلالية المفتوحة، المعاملات المالية، تطبيقات الهاتف الأصلية، وتشغيل تعليمات مجهولة المصدر دون عزل.

## البنية في سطر واحد

واجهة مستخدم تتصل بخدمة تطبيق موحّدة تضم منسق الوكيل، ومحرك السياسات، وسجل الأدوات، والذاكرة، وطابور الأعمال، وسجل التدقيق؛ ويمكن فصل هذه الوحدات إلى خدمات مستقلة عند الحاجة.

## تشغيل النواة محليًا

تحتاج إلى Python `3.12+`. بوابة النماذج الوهمية هي الافتراضية، ولذلك لا يلزم مفتاح API لتشغيل الاختبارات أو تجربة API الحالية.

```powershell
cd E:\OpenAI_Codex\Awn
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
pytest
uvicorn apps.api.main:app --reload
```

بعد التشغيل:

- فحص الخدمة: `http://127.0.0.1:8000/health`
- توثيق API التفاعلي: `http://127.0.0.1:8000/docs`

لاستخدام OpenAI، انسخ `.env.example` إلى `.env`، واختر `AWN_MODEL_PROVIDER=openai` ثم عيّن `AWN_OPENAI_MODEL` و`AWN_OPENAI_API_KEY`. لا تضف ملف `.env` إلى Git.

## المساهمة

قبل بدء أي تغيير:

1. راجع [PRODUCT.md](PRODUCT.md) للتأكد من أن التغيير داخل النطاق.
2. وثّق أي قرار معماري مؤثر في سجل قرارات معماري عند بدء التنفيذ.
3. أضف اختبارًا ومعيار قبول لأي سلوك جديد.
4. لا تضف أداة خارجية دون تعريف صلاحياتها ومخاطرها وآلية إيقافها.
